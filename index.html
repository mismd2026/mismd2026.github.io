経歴・概要

コストコホールセールジャパンにて約20年間、ITインフラ・セキュリティ領域に従事。2024年12月からは株式会社グリーンフーズマネジメントシステムで、インフラチームのマネジメントとインフラ全体の刷新を担当。

大規模ネットワーク構築、サーバー移設、Active Directoryの標準化（IAM）、セキュリティ監査対応（PCI DSS等）から、Python / GAS / PowerShell / IaCを活用した自動化・システム統合までを、要件定義から導入後の運用まで一貫して担当。

最大約20名規模のプロジェクトでPM / PLを担当し、米国本社のチームとは英語で調整。

ヘルプデスク時代から業務システムを自作し、Windows 10 移行では Sysprep イメージと自作の設定バッチで全店のPC設定を標準化した。

5　Works & Gap Bridging

実績・作品紹介

既存製品の境界に残る「仕様の隙間」を、どの構成で、何で埋めたか。各事例の右側に、根拠となる職務経歴と公開リポジトリを並べています。

開発の進め方

キッティング・資産管理、コールセンター、動画制作、貸出管理の4つのリポジトリは、同じ流れで作っています。生成AIを開発環境に組み込み、企画から公開までを短いサイクルで回します。

  1. 企画業務の課題を、5つの指標で要件に落とす各 README の「課題」「設計の判断」
  2. 設計構成図と判断理由を、コードと同じ場所に残すMermaid の構成図・状態遷移図
  3. 実装Python・TypeScript・GAS で機能を作る。AIのコーディング支援を使うFastAPI・SQLAlchemy・React
  4. 構成のコード化サーバー・端末・デプロイ先の状態をコードで定義するAnsible・Docker Compose・Helm
  5. 自動テスト・CI変更のたびにテストと静的検査を自動で実行するGitHub Actions・自動テスト計104件（pytest・Node）・ansible-lint
  6. 運用・計測動かした結果を記録し、次の改善につなげるジョブ記録・監査ログ・メトリクス
事例①

老朽化したインフラの刷新とID統合現職　インフラチームのマネジメント

適用システム構成
オンプレミスの Active Directory、単一のデータセンター、拠点ごとに契約した回線とプロキシ。機器はすべて単一構成で、本社の有線LANは管理されていなかった。
背景・課題
  • 処理が担当者ごとに属人化し、情報も一部の人にしかない
  • インフラが老朽化し、すべてが単一構成で障害に非常に弱い
  • その場しのぎで配線され、どこにハブがあり何とつながっているか誰も把握していない
  • ネットワーク内の衝突（コリジョン）で、通信が使えなくなりやすい
  • アカウントの作成・変更や資料依頼がマネージャー1人に集中し、チームの管理が行き届かない
  • 全社員が電話対応と記録を担い、電話番で昼食が取れない人が出る
実施内容
  1. 年間の支払いを金額の大きい順に洗い出し、データセンターとネットワークの費用を構成から見直し
  2. データセンターを NTT から OS1 へ。直接交渉し、冗長性を確保した構成で移設を計画
  3. 本社・各拠点の回線をアルテリアで基幹部分から刷新し、支出を削減
  4. ネットワークの管理を SASE サービスへ移し、より安定した基盤に
  5. SAML 認証を導入し、各 SaaS と連携
  6. オンプレ AD から Entra ID へ移行。Microsoft 365 の SSO と多要素認証を有効にし、既存PCは Hybrid Entra ID Join でオンプレ AD と Entra ID の両方に登録
  7. 障害点だったプロキシを移設し、ネットワークに負荷をかけずに切り替え
  8. 障害が集中していた本社の敷設LANを根元から敷設し直し、あわせて無線化
  9. PC設定を自動化し、チームの業務を個別の設定作業からプロファイル管理へ移行。マネージャーへの依頼集中を解消
  10. 電話対応の体制は総務部門の管轄のため、推奨構成を複数案提案。現在検討中で、相談があれば支援する体制をとっている
  11. 移設と並行して、IIS で公開していた HTML ベースの旧 Web サイトを WordPress へ移す計画を支援。経験のなかった担当者に、仕組みと使い方を教えた
結果
SaaS で運用する業務が増え、業務の質が向上した。PC設定の自動化により、チームは設定作業ではなくプロファイルの管理を担う体制になった。

Entra ID・Microsoft 365・SAML / SSO・MFA・Hybrid Entra ID Join・SASE・アルテリア回線・データセンター移設・IIS・WordPress

5つの指標との対応

  • コスト支払いの洗い出し、データセンターの直接交渉、回線の刷新
  • 信頼性・可用性冗長性を確保したデータセンター、単一構成の解消、LANの再敷設
  • セキュリティSASE、SAML 認証、Entra ID と多要素認証
  • 運用・保守性SSO で SaaS の利用を一本化、PC設定の自動化とプロファイル管理への移行、配線と構成の可視化
  • 性能・拡張性プロキシの移設、基幹回線の刷新、無線化

  • 役割ごとの権限分離と、全操作の監査ログを持つ管理システム（公開リポジトリ）
設計方針
Entra ID を起点に、Google Workspace へは SAML で SSO、SCIM でアカウントの作成・停止を自動化する。SCIM に対応しない SaaS は GAS / Python でアカウント状態を突き合わせて監査し、製品の境界で遮断が遅れる隙間をなくす。

アーキテクチャ方針

Windows・オンプレミス・高額SaaSを積み上げた構造から、GCP・Google Workspace・ChromeOS を軸にしたフルクラウド＆ゼロトラストの構成へ統合する。

Microsoft 環境が残る組織では、整えた Entra ID をそのまま生かし、Google Workspace と共存させてから段階的に移す。一度に置き換えず、業務を止めないことを優先する。

インフラの構成をコードで管理し（IaC）、開発と運用を同じパイプラインでつなぐ（DevOps）。変更はレビューと自動テストを通してから本番に反映し、同じ手順で何度でも再現できる状態を保つ。

2016年のクラウド比較、2022年の Azure 展開提案、2023年の AVS 化と Google Drive 移行、現職での Entra ID・SASE への移行と進めてきたクラウド化を、端末とアプリまで含めた統合に広げる。
